# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Financial control system for LAPIG (Laboratório de Processamento de Imagens e Geoprocessamento / UFG). Migrated from Google Sheets + Apps Script to a Vanilla JS + Supabase web app. The entire UI and documentation are in **Brazilian Portuguese (pt-BR)**.

## Running the App

No build step. Serve `frontend/` with any static file server:
```bash
cd frontend && python -m http.server 8080
```
Or use `abrir-site.bat` in the project root. **Must use HTTP** — `file://` breaks `<script type="module">` (pure-fns.js). Supabase credentials live in `frontend/js/supabase-config.js`.

## Dev Tooling

The frontend has no build step — all JS loads via `<script>` tags. For linting, testing, and CI, the project uses Node.js:
```bash
npm ci          # install dev dependencies (eslint, vitest)
npm run lint    # run ESLint on frontend/js/ e mcp/
npm test        # run Vitest on tests/
```

CI runs on GitHub Actions (`.github/workflows/ci.yml`) on push/PR to main/master.

- `048_janela_compromissos_dia_pagamento.sql` — o **saldo livre estava inflado todo mês**. `get_saldo_livre` cruza duas fontes com cortes diferentes: `realizado` vem do balancete (fechado em `data_referencia`) e os compromissos vinham do mês SEGUINTE a essa data. A 038 supunha que o balancete do mês M contém a folha de M — não contém: **as bolsas da FUNAPE são pagas no dia 07**, chega um balancete por mês e em dia imprevisível. Balancete emitido antes do dia 07 não tem a folha do próprio mês, e ela também não era compromisso: sumia no vão. Medido no 30.068 (balancete de 2026-08-03): 34.600 invisíveis — exatamente uma folha das 7 bolsas ativas —, saldo livre 92.600 em vez de 58.000. Três correções: **(A)** a janela começa no mês seguinte ao último COBERTO (dia > 07 → cobre o próprio mês; o dia 07 exato conta como não coberto, errando para "cabe menos"); **(B)** o filtro passa de `status = 'active'` para `<> 'cancelled'`, porque a janela agora pode começar no passado e bolsa encerrada dentro dela teve pagamento fora do balancete; **(C)** `balancete_defasagem_meses` mede do último mês coberto (devolvia 0 para 03/08 em agosto, escondendo o mês que faltava) e o retorno ganha `balancete_cobre_ate`. Gerada como **diff mínimo do corpo da 038**, não reescrita — uma reescrita minha já tinha divergido no `rastreia_compromissos` e no rollup. Roteiro em `tests/sql/test_048_janela_compromissos.sql` (+ `stub-048.sql`, com o 30.068 real mais uma bolsa encerrada e uma cancelada para exercitar (B)).
- `049_sinal_e_reclassificacao_de_bens.sql` — **`b` e `f` inflados**: no 30.068, Investimento aparecia estourado em R$ 152 mil com R$ 236 mil sobrando, e o saldo livre saía R$ 267 mil em vez de R$ 737 mil. Duas causas: (A) redutoras "( - )" de 7.1.3 vêm **sem parênteses na linha-folha** mas a conta-mãe as desconta — eram somadas; (B) a FUNAPE reclassifica equipamento: despesa em 7.1.3.20 → **estorno** em 7.1.1.08 (recuperação) → relançamento como doação de bens em 7.1.3.50 — o mapa só via a primeira perna. `saldo_atual` passa a ser **contribuição ao gasto** (redutora e estorno negativos); regras novas `7.1.3.50.06`/`7.1.3.50.02.94664`/`7.1.1.08.22`/`7.1.1.08.50` → `f` e `7.1.1.08.20` → `b`; `nao_mapeados` deixa de listar receita (7.1.1.01). Nenhuma RPC de cálculo mudou — todas somam `saldo_atual`. O parser grava com o sinal novo e **confere cada conta-mãe de 4 níveis contra a soma das folhas** (aviso na importação). Perda cambial fica fora de `f` (7.1.3.62, ignorada como despesa financeira). Conferência independente: o realizado corrigido + IR + câmbio fecha com a saída de caixa do balancete. Idempotente; NOTICE com o impacto por projeto. - `051_buriti_propostas_do_agente.sql` — a porta de escrita do **Buriti** (agente de IA): **ele propõe, um humano aplica**. Papel `agente` em `app_users` (lê o escopo de `user_projects`). **A barreira está no dado, não no caminho**: as policies de escrita da 033 checam escopo e não papel, e as RPCs definer de escrita só `assert_project_allowed` — um agente com centro atribuído gravaria por qualquer uma. Em vez de remendar cada uma, um **gatilho de statement `trg_bloqueia_agente` em TODA tabela de `public`** (exceto `propostas_agente`) recusa escrita quando `is_agente()`; gatilho dispara dentro de definer e `auth.uid()` segue sendo o do agente, então fecha PostgREST e RPCs atuais e futuras. **Tabela criada depois não ganha o gatilho sozinha** — rodar o BLOCO 1 de `tests/sql/test_051_buriti_propostas.sql` após migração que crie tabela. Storage: policy **restritiva** confina o agente ao bucket `propostas-agente` (pasta = `project_id`). `propostas_agente` (tipo balancete/bolsas/pergunta/aviso; status pendente/aplicada/rejeitada/respondida/obsoleta) só se escreve por RPC: `criar_proposta` (só agente, guard de escopo; mesma `chave` substitui a pendente anterior), `decidir_proposta` (só humano; rejeitar exige motivo — é o que o agente lê), `marcar_proposta_aplicada` (só humano). Para balancete a marcação é **atômica**: `upsert_balancete` aceita `proposta_id` e marca na mesma transação (reaplicar falha e não grava nada). `save_user_assignments` aceita `agente` e **recusa tirar alguém desse papel** (o seletor de `usuarios.js` mostraria "professor" para o agente e um Salvar desavisado lhe devolveria o poder de gravar; agora o seletor trava). **No MCP**, as tools `propor_balancete`/`listar_propostas`/`perguntar` (registradas com `buriti(...)`, só no MCP — `tests/ai-tools.test.js` garante que o Assistente do site não as tem) usam o MESMO parser e a mesma montagem de texto do site (`frontend/js/parsers/pdf-texto.js`; `frontend/js/package.json` com `type: module` existe só para o Node importar os parsers); a parte pura fica em `mcp/src/buriti-proposta.js` (testável sem as dependências do MCP) e as sugestões de rubrica em `mcp/src/buriti-sugestoes.js`. O pdf.js avisa por `console.log` ao carregar — stdout é o canal do MCP, por isso `index.js` desvia `console.log` para stderr. Instalação do Buriti (segundo servidor MCP, senha fora do chat) em `mcp/README.md`. Roteiro autoconferido (7 blocos, raise em falha) + `stub-051.sql` (auth.uid pelo JWT, helpers reais da 033 — o `is_admin()` do stub.sql é sempre true —, storage mínimo com RLS).

## Key Conventions

- **No frontend build step.** All JS is browser-native ES5/ES6 loaded via `<script>` tags, except `pure-fns.js` which loads as `<script type="module">` and bridges exports to `window` for classic scripts. Dev tooling (eslint, vitest) runs via Node.js (`package.json`).
- **Conventional commits:** `feat:`, `fix:`, `chore:`, `docs:` prefixes.
- **CSS design system:** `frontend/css/style.css` (~1760 lines) uses CSS custom properties for theming. LAPIG institutional colors, glassmorphism effects.
- **CDN with local fallback:** Libraries (Chart.js, Lucide, Supabase SDK, Mammoth, pdf.js + worker, SheetJS) load from CDN with SRI integrity hashes. If CDN fails, `frontend/vendor/` provides local copies — **as 7 cópias existem**; até 2026-08-28 faltavam `mammoth.browser.min.js` e `pdf.min.js`, e o fallback dos dois formatos de importação era só promessa no HTML. O `workerSrc` do pdf.js é escolhido em runtime (local só quando o próprio `pdf.min.js` veio do vendor — CDN nesse caso derrubaria o worker junto e cairia no "fake worker"). Versões, procedimento de atualização e conferência do hash em `frontend/vendor/README.md`; `.gitattributes` marca esses arquivos `-text` para não perderem a igualdade byte a byte com o upstream.
- **Keep-alive do Supabase via n8n:** `tools/n8n-keep-alive-lapig.json` (workflow) + `docs/keep-alive-n8n.md` (guia) evitam que o projeto gratuito do Supabase entre em pausa por inatividade (7 dias). A cada 2 dias, o workflow faz uma query de leitura idêntica à da landing page (`projects` ativos). Não altera dados.
- **Security:** CSP meta tag in `index.html`. Sentry integration in `supabase-config.js` for error monitoring.
- **Multi-tenancy por centro de custo (mig. 033 + 034):** cada usuário autenticado tem um papel (`admin`/`professor`) em `app_users` e centros de custo permitidos em `user_projects`. `auth.js` carrega o perfil no login (`Auth.isAdmin()`/`getRole()`/`getAllowedProjectIds()`) **antes** de `App.init()`. Professores veem/editam só os seus projetos — o RLS escopa todos os `from('projects')`, as views `security_invoker` e as RPCs invoker; admins veem tudo. **Desde a mig. 034 o professor também gerencia projetos** (cria — auto-atribuído a si em `user_projects` — e edita os seus via `save_project`) **e roda o Fechamento Mensal** (checklist escopado + reconciliação de bolsas via `apply_reconciliation` escopado); a mescla de duplicados (`merge_holders`, global) e a gestão de usuários (`save_user_assignments`) continuam admin-only. Só a rota **Usuários & Centros de Custo** (`usuarios.js`) tem `data-admin` no `<li>` (oculta no sidebar) + guard em `app.js` (Fechamento e Gestão de Projetos agora são professor-acessíveis). Criar logins continua no painel do Supabase (signup desativado); a anon key é pública, então o RLS é a barreira real — a service_role key **nunca** vai no frontend.
- **localStorage keys** use `cf_` prefix: `cf_selected_project_id`, `cf_dashboard_selected_projects`, `cf_plano_trabalho_project_id`, `cf_plano_trabalho_tab`, `cf_holders_tab`. (`cf_recon_project_id` foi aposentada.) **`cf_selected_project_id` é o "projeto atual" do app** e desde 2026-08-28 é lido por 5 telas, não 2: Projetos, Visão do Projeto, Bolsistas (semeia o filtro), Observações (`projectFilter: true` do `CrudPage`) e Saldos, que **destaca** a linha em vez de filtrar — filtrar destruiria o "Total em Conta", que é a soma de todos. Antes, os botões "Abrir" da Visão do Projeto gravavam a chave e só o Plano de Trabalho a lia: 3 dos 5 destinos abriam a lista global. Cada tela relê no `load()` e volta a "todos" se o id saiu do escopo.
- **Navegação com mudanças não salvas:** o `Router` expõe `registerGuard(fn)` e `registerDirtyChecker(fn)`, hoje consumidos **só por `projetos.js`**; `hasUnsavedChanges()` alimenta o `beforeunload` em `app.js` que avisa ao fechar/recarregar a aba. Mudanças não salvas no modo editor (Projetos) pedem confirmação antes de trocar de rota. `saldos.js` também registrava até a mig. 044 — a aba virou somente leitura e não tem mais estado a perder.
- **Edge Functions** ficam em `supabase/functions/`. Três, sendo **uma viva**: `assistente` (fase 3 da camada de IA — ver o bullet próprio abaixo). As duas de extração (`extract-plano-trabalho` e `extract-balancete`) eram proxies Ollama Cloud (`kimi-k2.6:cloud`) e estão **deprecated** desde 2026-05: o frontend não as chama mais — a extração é 100% determinística por `frontend/js/parsers/balancete-parser.js` (PDF→regex) e `frontend/js/parsers/pt-parser.js` (DOCX→mammoth→HTML→parser) — e permanecem deployadas como histórico. Deploy manual via `npx supabase functions deploy <name> --project-ref <ref>` (o repo não está linkado, e desde a CLI v2 o bundle sai pela API — não precisa de Docker; o passo a passo está em `supabase/functions/assistente/README.md`). O secret `OLLAMA_API_KEY` que as duas usavam **voltou a ser consumido em runtime**, agora pela `assistente`.
- **Servidor MCP** fica em `mcp/` (pacote Node próprio, `type: module`, sem relação com o frontend sem build). É a **fase 2** da camada de IA — adaptador fino sobre as RPCs de decisão das migrações 038/039, com uma regra dura: **zero lógica financeira no adaptador**, porque a fase 3 (aba no site) vai consumir as mesmas RPCs e duas implementações da mesma conta divergiriam. Autentica **por usuário** (`CF_EMAIL`/`CF_PASSWORD` no bloco `env` do cliente MCP): faz login de verdade no GoTrue e chama as RPCs com o JWT daquele usuário, então o RLS das migrações 033/034 é a barreira e o servidor não tem lógica de permissão própria. Tools (9): `listar_centros_de_custo`, `panorama`, `saldo_livre`, `simular_alocacao`, `consultar_bolsas` (colunas explícitas — CPF e e-mail nunca saem), `previsto_vs_realizado`, `projecao_de_caixa`, `plano_de_trabalho` e `quem_sou_eu`. As descrições das tools carregam o enquadramento das migrações porque é o que o modelo lê (shortlist com justificativa, não recomendação; declarar o que o número cobre; **`panorama` descreve e `simular_alocacao` ranqueia** — a ordem do panorama é alfabética e não é prioridade). As tools de leitura declaram o que **não** cobrem: `previsto_vs_realizado` só olha para trás, `projecao_de_caixa` só sabe prever bolsa e parte do saldo cadastrado no projeto (não do balancete), `plano_de_trabalho` é o orçado e não o executado. **Não existe tool `alertas` separada** de propósito: o `panorama` já traz os alertas de cada centro, e duas portas para o mesmo dado é o começo da inflação de tools que degrada a escolha do modelo. `panorama` exige a migração 040; as demais, as 038/039. Transporte stdio: **nada** em stdout além do protocolo — log vai para stderr. O enquadramento transversal (não calcular, não recomendar, declarar cobertura, **`panorama` descreve × `simular_alocacao` ranqueia**) mora no `instructions` do handshake, não repetido em cada descrição: o cliente lê uma vez **antes** de escolher a tool, e nove cópias custavam contexto em toda listagem — a descrição de cada tool ficou com o que só ela sabe (o que aquele número não cobre), mais a versão curta da regra nas duas em que a leitura errada é mais provável. As 9 tools declaram `readOnlyHint` (dica ao cliente, não barreira — a barreira é o RLS). `plano_de_trabalho` **projeta** os campos em vez de repassar o `to_jsonb(pt.*)` de `get_plano_ativo`, que traz `raw_extraction` — segunda cópia das rubricas e desembolsos já estruturados; a poda é no adaptador e não na RPC porque ela é contrato compartilhado com o frontend. **Duas conferências:** `npm test` (em `mcp/`) sobe o servidor como cliente MCP real e confere o contrato sem credencial nenhuma — funciona porque o login é preguiçoso (`config()` só é lida na primeira chamada de tool), e é o que roda no CI (job `mcp`), junto do `login-concorrente.js` — o cliente MCP chama tools em paralelo, e `entrar()` publicava o cliente antes de autenticar, então a 2ª chamada lia com a anon key e recebia **zero linha** em vez de erro (`total: 0` para admin); hoje o login é single-flight, e o teste usa um dublê que atrasa o login em vez de mock, porque sem atraso a corrida não acontece; `npm run smoke` exige banco e roda ponta a ponta. O smoke tem que ser rodado com **os dois logins**: as conferências de escopo têm expectativas opostas conforme o papel (professor barrado, admin passa) por dois caminhos — erro no definer com guard (`saldo_livre`) e ausência de linha no invoker (`panorama`) —, e `CF_SMOKE_PROJETO_ALHEIO=<uuid>` troca o uuid inexistente padrão por um centro de custo real alheio. Conferência marcada `ok~` passou **a vazio** (sem dado para exercitar): não é falha, mas também não é garantia — o rodapé lista quais foram. **Pendente (2ª rodada):** as respostas do modelo saem prolixas, e a pista é que o texto não nasce no adaptador — `nota`/`avisos`/`resumo.observacao` são devolvidos pelas **RPCs** (038/039/040) e chegam no payload de toda chamada, não só na escolha da tool. Enxugar ali muda o MCP **e** a futura aba do site de uma vez; podar no `tools.js` para resolver faria os dois divergirem, que é o que a arquitetura evita. Separar na nota o que **declara cobertura** (dado, tem de continuar) do que **instrui o leitor** (enquadramento, já vive no `instructions`), e fixar 2–3 perguntas de referência antes de mexer — ver a seção "Segunda rodada" em `mcp/README.md`.
- **Aba Assistente** (`frontend/js/ai/` + `frontend/js/pages/assistente.js` + Edge Function `assistente`) é a **fase 3** da camada de IA. **MCP não é o que se usa aqui**: MCP existe para conectar clientes de IA de terceiros; no próprio site é *tool calling* no formato nativo do provedor (Ollama Cloud, `/api/chat`). O que portou da fase 2 é `mcp/src/tools.js` e as descrições das tools — a parte cara de escrever. **O laço roda no browser**, não na Edge Function, por três razões independentes: (a) as tools chamam as RPCs pelo `supabaseClient` já logado — mesmo JWT, mesmo RLS, mesmo caminho das outras telas, sem repassar token nem manter uma segunda cópia do adaptador em Deno; (b) a tela mostra **ao vivo qual RPC está sendo consultada**, com o JSON cru dobrável embaixo de cada passo, e é assim que se confere a regra "todo número sai de RPC" sem acreditar na palavra do modelo — número na resposta sem passo correspondente é invenção; (c) ajustar prompt e descrição não exige deploy. À Edge Function sobrou só o que ela pode fazer sozinha: guardar a `OLLAMA_API_KEY` (que não pode ir num bundle público) e a allowlist de modelos que alimenta o seletor da tela — trocável pelo secret `ASSISTENTE_MODELOS`, sem redeploy. Ela **não** executa tool, não chama RPC, não guarda conversa e não tem lógica financeira; é um gateway de LLM para quem tem login, e o limite é honesto (quem tem login já enxerga pelo RLS o dado que o assistente consulta — o que a função impede é a chave vazar e anônimo usá-la). Os tetos (80 mensagens, 30 tools, 400 mil chars, 120 s; e no cliente 6 rodadas e 60 mil chars por resultado de tool) são freio contra laço infinito, não segurança. **Dois adaptadores sobre as mesmas RPCs** (`mcp/src/tools.js` e `frontend/js/ai/tools.js`) existem separados por encanamento — stdio/zod/npm × `<script type="module">` sem build —, não por terem regras diferentes, e é o tipo de par que deriva em silêncio: `tests/ai-tools.test.js` lê o fonte do MCP como texto e trava a **lista de tools** e o bloco das **quatro regras** transversais, comparado palavra por palavra (as descrições individuais podem divergir de propósito). Detalhes de protocolo que quebram em produção e por isso viraram teste (`tests/ai-agent.test.js`, com modelo e banco dublês): `tool_calls[].function.arguments` chega como **objeto** no Ollama nativo e como **string JSON** em modelo treinado no formato da OpenAI (o laço aceita os dois, e devolve `tool_call_id` quando existe); o resultado volta como `{ role: 'tool', tool_name, content }`; **erro de tool volta ao modelo como resultado, não como exceção** (nome ambíguo é recuperável — a mensagem já lista os candidatos); e falha no meio de uma rodada faz o histórico voltar **inteiro** ao ponto anterior, porque remover só a última pergunta deixaria um `assistant` com `tool_calls` sem as respostas `tool`, e o par quebrado derruba a chamada seguinte. `js/ai/markdown.js` existe separado da página porque é onde texto de fora vira HTML (o modelo repete nome de bolsista e de projeto vindos do banco): escapa **antes** de formatar e **não** trata `_` como itálico — os nomes de campo das RPCs são snake_case e seriam despedaçados justamente nos termos que a resposta mais cita (`tests/ai-markdown.test.js`). A aba **não exigiu mudança de CSP**: `functions.invoke` sai para a mesma origem do Supabase, já em `connect-src`. **A pendência da verbosidade (2ª rodada) vale igual aqui** — `nota`/`avisos`/`resumo.observacao` vêm das RPCs 038/039/040 e chegam nesta aba pelo mesmo payload; enxugar é na migração, e agora muda **dois** consumidores de uma vez.
- **Ambientes de teste local do banco** ficam em `tools/replica-local/` (README com as receitas): nível sintético (5 centros de custo, um por restrição, sem credencial), réplica do banco real raspada de PII (container `cf-real`) e a **stack Supabase local** (`supabase/config.toml` versionado, só db+auth+rest ligados). Só a stack completa testa o que os adaptadores podem errar — grant a `authenticated`, exposição de RPC, parsing de JWT e tradução de erro; Postgres puro valida cálculo, não transporte. Dumps nunca são versionados (`tools/replica-local/dump/` no `.gitignore`).
- **Parsers e componentes determinísticos** ficam em `frontend/js/parsers/` (balancete + plano de trabalho em DOCX e em PDF + tabela de aliases de rubrica + detector de modelo de plano + planilha de bolsas FUNAPE) e `frontend/js/components/` (split-views PDF e DOCX). O plano PROAD tem **dois** parsers porque o pdf.js não entrega estrutura de tabela: `pt-parser.js` (DOCX→mammoth→`<table>`) e `pt-pdf-parser.js` (PDF→pdf.js→linhas, com o total declarado de cada letra como árbitro sobre as folhas — ver `docs/planos-fora-do-padrao.md`). São módulos ES carregados via `<script type="module">` no `index.html` e bridge-ados ao `window` para uso pelos scripts clássicos. `bolsa-parser.js` lê XLSX via **SheetJS** (`window.XLSX`, CDN `xlsx@0.18.5` + fallback em `frontend/vendor/xlsx.full.min.js`) e devolve `{ data, warnings }`; `bolsa-comparator.js` compara planilha × banco e devolve `{ novos, removidos, alterados, iguais }` (com `matchKind` `link`/`new` e `existingHolderId` para evitar duplicados globais).
- **Página "Visão do Projeto" (`hub.js`)** é uma tela agregadora **experimental** (somente leitura) que reúne os 4 KPIs-chave de um projeto e atalhos "Abrir" para cada área. Compartilha o projeto selecionado com a aba Projetos (`cf_selected_project_id`). Registrada no `Router` como `hub` e no sidebar com ícone `telescope`.
- **Fila de importação genérica (`frontend/js/import-queue.js`)** — componente global `ImportQueue` (classic script) com o contrato de handler documentado no cabeçalho do arquivo. Handlers existentes: plano DOCX e balancete PDF (`PlanoTrabalhoPage.getImportHandlers()`) e bolsas XLSX (`HoldersPage.getBolsaImportHandler()`). A página **Fechamento Mensal** (`fechamento.js`, rota `fechamento`) abre a fila com os 3 handlers de uma vez (roteamento por extensão) e mostra o checklist da competência: projetos FUNAPE ativos × balancete recebido × planilha de bolsas conferida × plano ativo. Três pontos do contrato existem para os **planos fora do padrão** (ver `docs/planos-fora-do-padrao.md`): `fallbackExt(name)` reivindica formatos sem leitor automático só quando nenhum handler os quis por `validExt` (impede o handler de plano de roubar o XLSX de bolsas no Fechamento); um erro de `parse` com `.rerouteTo = '<type>'` reentrega o arquivo a outro handler — é assim que um **PDF de plano** roteado como balancete volta para o handler de plano; e `manualFallback(file)` faz a tela de erro oferecer **"Preencher manualmente"** em vez de só "Pular", reaproveitando o formulário de revisão (que já é editor completo) com o arquivo original anexado como comprovante.
- **Sino de alertas** (`frontend/js/notifications.js`, global `Notifications`) é montado no **boot** (`app.js`), não pela página que por acaso o alimentava. Até 2026-08-28 morava em `dashboard.js`: os listeners só nasciam dentro de `DashboardPage.load()`, então — sendo a landing `projetos` — **o primeiro clique no sino não fazia nada**; e depois de visitar a Visão Geral ele passava a exibir os alertas do **filtro daquela tela**, escopo que seguia valendo nas outras páginas sem nada dizer isso. Agora cobre todos os centros **ativos que o usuário enxerga** (o RLS das 033/034 escopa; não há filtro no cliente). Três estados de propósito: `consultando…` antes da primeira resposta (sino que diz "tudo certo" antes de perguntar é silêncio otimista), `indisponível` com badge `!` na falha, e a contagem real.
- **Falha de consulta nunca vira zero** — regra transversal de `projetos.js`, `hub.js` e `dashboard.js`: cada carga guarda `loadErrors` por fonte, a tela abre com banner do que não pôde ser consultado, e os KPIs afetados renderizam `—` em vez de `formatBRL(0)`. O padrão antigo (`console.warn` + `|| []`) produzia tela **plausível e errada**: bolsas que não carregaram viravam "0 bolsas ativas", indistinguível de projeto sem bolsista. No Dashboard a variante pior era o fallback N+1 de `calcAggregatedMonthly`, que descartava em silêncio os centros que falhavam e **somava o resto** — consolidado parcial com cara de completo; agora conta os que faltaram e o banner diz que ficaram fora da soma. `enterEditorMode` recusa simular quando as bolsas falharam.
- **Detalhe técnico só para admin** (`detalheTecnico()` em `supabase-config.js`): nome de migração, comando de deploy e nome de secret são acionáveis para quem administra e ruído sem saída para o professor, que não tem o painel do Supabase. Aplicado em `fechamento.js`, `holders.js`, `assistente.js`, `ai/agent.js` e `ai/tools.js`. **Não é segurança** — nada disso é segredo e o RLS é a barreira real. A cópia do MCP (`mcp/src/tools.js`) mantém o texto técnico de propósito: lá não há sessão com papel, e quem configurou o cliente é quem consegue rodar a migração — divergência de público, não de regra (`tests/ai-agent.test.js` cobre os dois papéis).
- **Página Buriti** (`frontend/js/pages/buriti.js`, rota `buriti`, sidebar "Rotina Mensal", ícone `palmtree`) é a caixa de propostas do agente (mig. 051), **feita para o celular** (cartões em coluna, botões de 44px em largura total abaixo de 640px). Não grava nada por conta própria: "Revisar e aplicar" chama `PlanoTrabalhoPage.revisarPropostaBalancete`, que baixa o PDF do bucket `propostas-agente` e abre a **mesma `ImportQueue` e a mesma revisão** da importação comum (a fila ganhou `files` opcional para pular a seleção); a sugestão do Buriti vem pré-selecionada com a justificativa, e salvar grava por `upsert_balancete` com `proposta_id` (marca na mesma transação). "Rejeitar" (motivo obrigatório) e "Responder" usam `decidir_proposta`. O Fechamento Mensal mostra as pendentes (banner + atalho na coluna Balancete), best-effort: sem a 051 o checklist segue igual.
- **Sidebar em seções** (`index.html` + `.sidebar__section` no CSS): "Rotina Mensal" (Fechamento, Saldos), "Acompanhamento" (Projetos, Visão do Projeto, Plano de Trabalho, Visão Geral), "Cadastros" (Bolsistas, Gestão de Projetos, Usuários & Centros de Custo [admin], Desembolsos, Observações). Itens `data-admin` são ocultados para professores em `app.js` (o RLS é a barreira real; o sidebar é só UX) — desde a mig. 034 só **Usuários & Centros de Custo** é `data-admin` (Fechamento e Gestão de Projetos ficaram professor-acessíveis).
- **Publicação:** `.github/workflows/deploy.yml` publica `frontend/` no GitHub Pages (Settings → Pages → Source: GitHub Actions). **Antes de tornar o repo público**, cumprir o checklist de `docs/seguranca-publicacao.md` — em especial desativar signup no Supabase Auth (a anon key é pública; a proteção é signup fechado + RLS `to authenticated`).
- **A projeção mensal vem da RPC, não do navegador.** Fora da simulação `projetos.js` usa o resultado de `calc_project_monthly`; o `SimulationEngine` só responde **dentro** dela, onde as bolsas em edição ainda não existem no banco. Até 2026-08-28 a tela buscava a RPC, **descartava o resultado** e recalculava localmente no caminho normal — duas implementações da mesma conta, livres para divergir do Dashboard e do Assistente, contra a regra que o próprio projeto escreveu para a camada de IA. O seletor "Desconto de Bolsas" segue instantâneo porque é **parâmetro** da RPC: trocá-lo refaz a pergunta (`setBalanceStatus` é `async`), não a conta.
- **All monetary values** are stored and calculated as numeric (no integer cents). Display uses `formatBRL()`.
- **Default landing page** is `projetos`, not dashboard — e a **re-inicialização** (relogin) cai no mesmo `projetos` quando não há rota corrente. Era `saldos`, que desde a mig. 044 é um relatório somente leitura: reentrar no app por ali punha a pessoa numa tela onde não há o que fazer.
